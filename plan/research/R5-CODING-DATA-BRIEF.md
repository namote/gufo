# R5 코딩 강화 브리프 1단계: 자료와 평가 도구

배경은 `plan/research/IDEAS.md`의 R5에 있다. activation steering(ITI 방식)으로 모델이 할 줄은 알지만 잘 하지 않는 행동을 더 하게 만든다. 이번 대상은 **꼼꼼한 코딩**이다.

- 꼼꼼한 코딩의 내용: 엣지 케이스 확인, 입력 검증, 간단한 자기 검증(예시 실행, assert), 정확한 복잡도와 주의점 설명.
- 방향은 `d_L = mean(모범 답안 토큰 활성) − mean(자기 답 토큰 활성)`이다. 같은 문제끼리 짝지어 주제 차이를 상쇄한다.
- 이번 단계는 **자료와 평가 도구만** 만든다. 엔진(답 토큰 활성 수집, 더하기 모드)은 다른 작업자가 따로 만든다.

## 만들 것 (`build/b1/r5-coding/`)

1. **문제 세트.** Python 함수 문제 최소 100개.
   - 각 문제는 지시문, 함수 시그니처, 숨은 테스트(엣지 케이스 위주: 빈 입력, 경계값, 중복, 음수, 유니코드, 큰 입력, 잘못된 타입 등)를 가진다.
   - 난이도와 종류를 섞는다: 문자열, 리스트, 딕셔너리, 수학, 날짜, 파싱, 간단한 알고리즘.
   - 한국어 지시문과 영어 지시문을 섞는다(약 절반씩).
   - 분할: 방향용 60, 세기 학습용 20, **평가용 20 이상(완전히 분리)**.
   - 유명 벤치마크 문제를 그대로 베끼지 않는다. 직접 만든다.
2. **모범 답안.** 방향용과 세기 학습용 문제마다 하나씩 쓴다.
   - 실제 모델 답과 길이와 형식이 비슷해야 한다. 설명 몇 줄과 코드 블록 하나로, 지나치게 길지 않게 쓴다. 길이나 형식 차이가 방향에 섞이지 않게 하기 위해서다.
   - 엣지 케이스 처리와 짧은 검증이 드러나야 한다.
   - **모든 모범 답안 코드는 숨은 테스트를 통과해야 한다.** CPU에서 검증한다.
3. **모델 자기 답 생성 스크립트.** 나중에 메인 세션이 GPU 패스에서 돌린다.
   - 서버는 `127.0.0.1:18740` chat completions, 모델 `gufo-flash-next`.
   - greedy, thinking 없음, 600토큰. 요청에 `abliteration: {"enabled": false}`를 넣는다.
   - 결과를 문제별로 저장하고, 코드 블록을 추출해 숨은 테스트 통과 여부를 기록한다.
4. **평가 도구.**
   - 입력: 생성 결과 JSONL(설정 이름별).
   - 각 답의 코드 블록을 추출해 숨은 테스트를 실행한다.
   - **모델이 만든 코드는 반드시 격리해서 실행한다.** docker `--network none`, 읽기 전용, 시간 제한, 메모리 제한. 기존 이미지 중 python3가 있는 것을 쓰거나 `python:3` 계열 로컬 이미지를 확인한다. 이미지를 새로 받아야 하면 보고만 하고 받지 않는다.
   - 출력: 설정별 통과율, 문제별 결과, 엣지 케이스 테스트만 따로 본 통과율.
   - 설정 비교 표를 출력한다.
5. **README.md.** 파일 목록, GPU 패스 실행 순서, 예상 시간을 적는다.
