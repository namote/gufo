# 연구 아이디어 (2026-11-11 등록)

순서는 등록 순서다. 각 항목은 착수할 때 단계별 계획 문서로 옮긴다.

## R1. 양자화 오차 보정: EoRA, 그다음 층별 어댑터

**목표:** 비트를 낮춘 팩(3.0~3.5 bpw)에 작은 FP16 보정을 붙여 c03(4.04 bpw) 수준의 KL을 맞춘다. 디코드와 프리필 MoE 가중치 스트림이 비트 수에 비례해 줄어드는 만큼 빨라지는 것이 가치다. 4.04 bpw에 그냥 붙이면 연구 결과상 이득이 작다.

**단계:**

- **R1-1. EoRA 오프라인 계산 (학습 없음).**
  - 대상: attention과 GDN의 projection, 공유 전문가, LM head. MoE 전문가는 제외한다.
  - 방법:
    1. 원본 BF16 가중치와 EXL3 복원 가중치의 차이 `ΔW`를 구한다.
    2. 보정 활성값 공분산의 고유공간으로 옮긴 뒤 SVD한다. 랭크는 32~128.
  - 참조 경로(PyTorch, 블록 단위)에서 KL 개선을 측정한다. 효과가 없으면 여기서 멈춘다.
  - 원본: 외장 디스크 `AI/models/qwen3.8-flash-next/hf-bf16-20261030`.
  - 저비트 후보: 27B `exl3-w8 3.0/3.5bpw`, Flash-Next Kyojin 3.05. 새 양자화가 필요하면 사용자에게 먼저 묻는다.
- **R1-2. 층별 bottleneck 어댑터 (학습).**
  - 구조: 잔차 스트림에 `x + W2·σ(W1·x)`(2560→256→2560)를 넣고, EoRA 결과로 초기화한다.
  - 학습: 블록 단위 증류로 원본 블록 출력에 맞춘다. EXL3 블록 하나를 FP16으로 풀어 고정하고 어댑터만 학습한다.
  - 마지막으로 LM head를 top-k logit KL로 미세조정한다.
  - 일반화를 확인한다: 한국어, 코드, 긴 컨텍스트 KL을 학습 분포 밖에서 잰다.
- **R1-3. 엔진 반영.**
  - 어댑터 로더와 `y = EXL3(W)x + B(Ax)` 경로(디코드 GEMV, 프리필 GEMM)를 만든다.
  - 그래프 캡처, 배치 디코드, MTP 검증 경로에도 넣는다.
  - 판정: "저비트 + 보정"이 c03보다 빠르고 KL이 같거나 낮아야 채택한다.

**근거:**

- EoRA(arXiv 2410.21271): 학습 없이 몇 분이면 되고, GPTQModel에 통합돼 있다.
- LQER(ICML 2024): W4A8에서 rank 32로 PPL 증가 평균 0.15.
- PV-Tuning/AQLM, QuIP#/QTIP의 미세조정: 2비트에서 이득이 크다.
- exllamav3 README 기능 목록에 LoRA가 있다. gufo에는 LoRA 경로가 없다.

## R2. 동적 다중 프로파일 abliteration (감지했을 때만 켜기)

**목표:**

- 평소에는 OFF로 원본 그대로, 원본 속도로 답한다.
- 프로파일마다 감지기를 두고, 기준을 넘은 프로파일만 켠다. 프로파일은 서로 합치지 않고 따로 둔다(사용자 결정, 2026-11-11).

**근거 측정 (2026-11-11):**

- **감지 성능 (오프라인 ROC):** `build/b1/ablit-pol-20261111/roc.py`. 같은 주제의 다른 문장이 학습과 검증 절반에 섞여 있어 낙관적인 수치다.

| 감지기 | 층 | AUC | 일반 질문 오탐 1%일 때 재현율 |
| --- | --- | --- | --- |
| 정치 | L38 | 0.985 (대조 사건), 0.994 (일반 질문) | 81% |
| 거절 | L38 | 0.985 | 92% |

  - 거절 감지기는 중국 민감 질문의 66%에도 반응한다. 두 신호가 겹친다.
- **현재 ON의 속도 비용:** 운영 c03에서 같은 질문 256토큰, 4회씩 측정했다.
  - OFF 42.3 tok/s, ON(거절 프로파일 writer a2 m05) 38.7 tok/s로 **-8.5%**.
  - 패스마다 96곳에서 별도 projection 커널이 돈다.

**설계:**

- **설정:** `--abliteration-profiles DIR`
  - 디렉터리의 프로파일 각각이 방향, 강도, `trigger {layer, threshold, scope}`를 가진다.
  - 단일 옵션 원칙에 맞게 기존 `--abliteration-profile`을 대체하는 방향으로 검토한다.
- **감지:**
  - 패스마다 감지 층의 마지막 행(디코드는 각 행)에서 프로파일별 점수 `<h, d>`를 계산하는 작은 커널을 하나 돌린다.
  - **점수는 logits와 같은 전송으로 host에 보낸다.** 추가 동기화가 없다.
  - OFF 요청의 비용 목표는 0.5% 이하다.
- **억제와 강화:** 프로파일마다 억제(`y − s·d·(d·y)`) 또는 강화(`y + α·d`, 또는 음수 세기)를 고른다(R5).
- **적용:**
  - 프리필이 끝날 때 점수가 기준을 넘은 프로파일을 켠다.
  - 디코드 중에도 넘으면 그 토큰부터 계속 켜 둔다(sticky).
  - 여러 프로파일이 동시에 켜지면 방향들을 직교화해서 함께 제거한다(기존 k-direction 경로).
- **프롬프트 KV 처리:** 두 방식을 품질로 비교해 고른다.
  - A1: 생성부터만 ON
  - A2: 감지된 요청만 ON으로 다시 프리필
- **ON 비용 줄이기:**
  - projection을 기존 잔차 Combine 커널과 writer 경로에 합쳐서, ON 비용을 -8.5%에서 1~2% 수준으로 낮춘다.
  - 이 작업은 동적 방식과 별개로 항상 ON인 경우에도 이득이다.
- **보고:**
  - 응답에 `abliteration: {triggered: [...], scores: {...}, position}`를 넣는다.
  - `/props`에 로드된 프로파일과 기준치를 보여 준다.
- **캐시:**
  - 프로파일 조합마다 continuation identity를 분리한다(현행 ON/OFF 분리를 확장).
  - 전환할 때 그래프를 다시 기록하는 비용을 측정한다.

**단계:**

- **R2-1. 기준치 확정.**
  - 정치 평가 질문을 학습에 쓰지 않은 주제로 늘리고, 사실 체크리스트로 채점한다.
  - 일반 질문 KL과 답변 품질을 확인한다.
  - 기준치를 오탐 1% 이하에서 고른다.
- **R2-2. 엔진 구현.** 다중 프로파일 로드, 감지 커널, 점수 전송, 요청 중간 전환, 보고.
  - CPU/단위 테스트 → 검토 → 수정 → 재검토 순서로 진행한다.
- **R2-3. projection 커널 합치기.**
- **R2-4. 통합 확인** (GPU 1회):
  - OFF 속도가 지금과 같은지 (±0.5%)
  - 감지 정확도
  - 정치·거절·일반 질문 품질
  - A1과 A2 비교
  - 캐시 재사용과 분리
- **R2-5. 운영 반영.**

**한계:**

- 거절 방향만으로는 순화(공식 입장 서술)를 잡지 못한다. 그래서 정치 프로파일을 따로 둔다(R3).

## R5. 모범 답안 대비 강화 방향 (activation steering, ITI 방식)

**목표:** 모델이 할 줄은 알지만 잘 하지 않는 행동을 더 하게 만든다. 예: 꼼꼼한 코딩(엣지 케이스 확인, 검증), 자연스러운 한국어(번역투와 한자 줄이기), 간결함. LoRA와 달리 역전파 없이 순전파와 추론 경로만 쓴다.

**방법:**

1. **데이터:** 같은 질문마다 모범 답안(사람이나 큰 모델의 답)과 자기 답(모델의 실제 출력)을 준비한다. 처음에는 대상 하나로 50~100쌍. 길이와 형식은 비슷하게 맞춘다.
2. **방향:** teacher forcing으로 답 토큰들의 층별 활성 평균을 모은다. `d_L = mean(모범) − mean(자기)`.
   - 같은 질문끼리 짝지어 주제 차이를 상쇄한다.
   - projected 방식과 k개 방향으로 표면 특징(길이, 언어, 형식)을 줄인다.
3. **적용:** `y ← y + α_L·d_L` 더하기 모드, 또는 음수 세기(기존 성분 증폭).
4. **강도 학습:** R4 채점과 SPSA로 층별 α를 학습한다.
   - 목표: 학습에 안 쓴 질문의 모범 답 로그확률 증가.
   - 벌점: 일반 답 로그확률 손실.
5. **판정:** 학습에 안 쓴 질문으로 확인한다.
   - 답 원문
   - 일반 품질
   - 능력 대상(코딩)이면 실제 테스트 통과율

**필요한 엔진 작업:**

- 수집기 확장: 답 토큰 평균 활성 수집. R4 채점 경로를 재사용한다.
- 더하기 모드, 음수 세기 허용.
- 둘 다 R2 동적 프로파일 설계에 "억제 또는 강화" 선택으로 넣는다.

**한계:**

- 새 지식이나 기술은 가르치지 못한다. 그런 것은 LoRA 계열 학습이 필요하다.
- 비용 비교: 방향은 전체 약 12만 개 숫자이고, 추론 비용은 거의 0이다. LoRA는 수백만 개 이상이고, 이 환경(EXL3, 추론 전용)에서는 역전파가 현실적이지 않다.

## R6. 자기 개선 루프 (steering → 검증 → 압축 → LoRA)

1. R5로 끈기와 자기 검증 방향을 만들어, 어려운 문제를 포기하지 않고 끝까지 풀게 한다. 루프를 감지하고, 강도는 SPSA로 맞춘다.
2. 자동 검증으로 성공한 풀이만 남긴다(테스트가 있는 코딩, 정답이 있는 수학).
3. 성공한 풀이를 모델에게 압축하게 한다(헛걸음과 실수 구간을 뺀다). 압축본으로 다시 풀어도 맞는지 검증한다.
4. 압축된 성공 풀이로 LoRA를 학습한다.
   - 27B BF16으로 먼저 검증한다.
   - Flash-Next는 QLoRA 도구와 ROCm 가능성을 따로 조사한다.
   - 대안: 정리본 대 원래 풀이의 R5 방향.
5. 반복한다.

대응 연구: STaR, Expert Iteration, Rejection-sampling FT, 풀이 압축(TokenSkip, C3oT, O1-Pruner 계열).

## R7. 만족도 방향 (선호 대비)과 해석

**데이터:** 같은 질문에 만족도가 높은 답과 낮은 답(공개 선호 데이터의 chosen/rejected, 또는 우리 사용 기록의 평가).

**방법:**

- 답 토큰 활성 평균으로 `d = mean(높음) − mean(낮음)`을 구한다(R5 수집기).
- **해석:**
  - logit lens: 방향을 LM head에 통과시켜 이 방향이 올리는 토큰과 내리는 토큰을 본다.
  - 층별 분리도(AUC)로 어디서 생기는지 본다.
  - 다른 방향(거절, 정치, 끈기, 간결)과의 코사인을 본다. 예: 만족도 방향이 아첨과 얼마나 겹치는가.
- **쓰임:**
  1. 싼 보상 신호: 답의 방향 점수를 SPSA 목표나 R6의 필터로 쓴다.
  2. 강화 프로파일(R5).

**주의:** 만족도는 아첨, 장황함, 자신감 과장과 섞이기 쉽다(Goodhart). 반드시 사실성과 일반 품질 지표를 함께 본다.

### R7 추가: 감정과 자신감 방향

| 실험 | 대비 데이터 | 확인할 것 |
| --- | --- | --- |
| 자신감 | 확신하는 답 대 망설이는 답, 맞힌 답 대 틀린 답 | 정답 여부와의 상관. 할루시네이션 감지기 후보 |
| 상대의 분노 인식 | 화난 고객 대 차분한 고객 (같은 내용, 말투만 다름) | 어느 층에서 인식하는지 |
| 자신의 분노 표현 | 분노 스크립트 대 차분한 스크립트 | 인식 방향과의 각도 |
| 압박과 굴복 | 화난 사용자가 틀린 주장을 할 때 | 분노 인식이 아첨·굴복 방향을 함께 켜는지 |

- **응용:** 화난 고객이 감지되면 "차분하고 공감하되 사실은 굽히지 않는" 강화 프로파일을 켠다.
- **바로 가능한 것:** 프롬프트 쪽 방향(인식)은 지금 수집기와 ROC로 바로 가능하다. 답 쪽 방향(표현, 자신감 있는 답)은 R5 답 토큰 수집기가 생긴 뒤에 한다.

## R8. 정직 방향(진실, 거짓말, 모름)과 보안 신중함 방향

**정직 (할루시네이션 감소):**

- **대비 데이터:**
  - 진실: 아는 사실을 그대로 말하게 함
  - 거짓말: 아는 사실을 일부러 틀리게 말하라고 지시
  - 모름: 존재하지 않는 인물이나 논문, 지나치게 세부적인 숫자를 물음
- **쓰임:**
  - "모름" 방향이 켜진 채 답할 때 확신이 낮다고 표시한다(감지).
  - 모를 때 모른다고 말하는 방향을 강화한다(ITI 방식).
- **주의:** 지시한 거짓말과 저절로 생기는 할루시네이션이 같은 방향이라는 보장이 없다. 실제 할루시네이션 사례로 검증한다.
- **참고:** Azaria & Mitchell, Marks & Tegmark(진실의 기하), Burns et al.(CCS), Li et al.(ITI).

**보안 신중함 (안전사고 예방, 코딩 에이전트):**

- **대비 데이터:** 같은 작업에 대해 "위험을 짚고 안전하게 처리" 대 "그냥 실행".
  - 비밀값 노출, 입력 검증, 인젝션
  - `rm -rf`, 강제 push, 운영 DB 변경, 권한 변경 전 확인
  - 코드 리뷰 중 취약점 지적
- **적용:** 위험 명령이나 보안 민감 코드가 감지될 때만 켜는 강화 프로파일(R2와 R5).

### 강화(steering) 관련 연구 근거 (2026-11-12 조사)

- **Sinii et al. 2025 (arXiv 2505.18706):** 층마다 bias 벡터 하나만 RL로 학습해 수학 추론에서 전체 RL 튜닝에 근접했다. 추가 파라미터는 8B 기준 0.0016%다. R5와 R6에서 층별 벡터 학습의 근거다.
- **정리 증명 steering (arXiv 2502.15507), Riemannian steering:** 추론할 때 더하기만으로 성능이 올랐다.
- **K-CAST (arXiv 2505.12189):** 정적 steering은 실패했고, 조건부(감지형)일 때 최대 +15점이었다. R2 감지형의 근거다.
- **CAA (arXiv 2312.06681), Persona vectors (Anthropic, arXiv 2507.21509), ITI:** 행동과 성격 방향의 감시와 조절이 확립돼 있다. persona vectors는 코드가 공개돼 있다.
- **한계 (Tan et al., arXiv 2407.12404):** 입력마다 효과가 다르고 일부는 반대로 나온다. 데이터셋 품질이 좌우한다. 학습에 안 쓴 데이터와 다양한 프롬프트로 검증한다.
