# 연구 아이디어 (2026-11-11 등록)

순서는 등록 순서다. 각 항목은 착수할 때 단계별 계획 문서로 옮긴다.

## R1. 양자화 오차 보정: EoRA, 그다음 층별 어댑터

**목표:** 비트를 낮춘 팩(3.0~3.5 bpw)에 작은 FP16 보정을 붙여 c03(4.04 bpw) 수준의 KL을 맞춘다. 디코드와 프리필 MoE 가중치 스트림이 비트 수에 비례해 줄어드는 만큼 빨라지는 것이 가치다. 4.04 bpw에 그냥 붙이면 연구 결과상 이득이 작다.

**단계:**

- **R1-1. EoRA 오프라인 계산 (학습 없음).**
  - 대상: attention과 GDN의 projection, 공유 전문가, LM head. MoE 전문가는 제외한다.
  - 방법:
    1. 원본 BF16 가중치와 EXL3 복원 가중치의 차이 `ΔW`를 구한다.
    2. 보정 활성값 공분산의 고유공간으로 옮긴 뒤 SVD한다. 랭크는 32~128.
  - 참조 경로(PyTorch, 블록 단위)에서 KL 개선을 측정한다. 효과가 없으면 여기서 멈춘다.
  - 원본: 외장 디스크 `AI/models/qwen3.8-flash-next/hf-bf16-20261030`.
  - 저비트 후보: 27B `exl3-w8 3.0/3.5bpw`, Flash-Next Kyojin 3.05. 새 양자화가 필요하면 사용자에게 먼저 묻는다.
- **R1-2. 층별 bottleneck 어댑터 (학습).**
  - 구조: 잔차 스트림에 `x + W2·σ(W1·x)`(2560→256→2560)를 넣고, EoRA 결과로 초기화한다.
  - 학습: 블록 단위 증류로 원본 블록 출력에 맞춘다. EXL3 블록 하나를 FP16으로 풀어 고정하고 어댑터만 학습한다.
  - 마지막으로 LM head를 top-k logit KL로 미세조정한다.
  - 일반화를 확인한다: 한국어, 코드, 긴 컨텍스트 KL을 학습 분포 밖에서 잰다.
- **R1-3. 엔진 반영.**
  - 어댑터 로더와 `y = EXL3(W)x + B(Ax)` 경로(디코드 GEMV, 프리필 GEMM)를 만든다.
  - 그래프 캡처, 배치 디코드, MTP 검증 경로에도 넣는다.
  - 판정: "저비트 + 보정"이 c03보다 빠르고 KL이 같거나 낮아야 채택한다.

**근거:**

- EoRA(arXiv 2410.21271): 학습 없이 몇 분이면 되고, GPTQModel에 통합돼 있다.
- LQER(ICML 2024): W4A8에서 rank 32로 PPL 증가 평균 0.15.
- PV-Tuning/AQLM, QuIP#/QTIP의 미세조정: 2비트에서 이득이 크다.
- exllamav3 README 기능 목록에 LoRA가 있다. gufo에는 LoRA 경로가 없다.

## R2. 동적 abliteration (거절 신호를 감지했을 때만 켜기)

**목표:** 평소에는 OFF로 원본 그대로 답하고, 거절 방향 활성이 강할 때만 자동으로 ON한다. 일반 답변의 품질 손실(OFF 대비 KL)을 없애는 것이 목적이다.

**단계:**

- **R2-0. 필요성 확인.**
  - 항상 ON일 때 일반 질문에서 OFF 대비 KL과 답변 품질 차이를 잰다. 첫 토큰이 아니라 전체 응답 기준이다.
  - 차이가 무시할 만하면 동적 방식은 필요 없다. 기존 search 로그의 first-token KL도 참고한다.
- **R2-1. 감지기.**
  - 신호: 프롬프트 마지막 토큰의 L36 잔차(HC 스트림별)를 거절 방향에 투영한 점수 `s = <h, d>`.
  - 임계값: 기존 수집 데이터(거절/일반 프롬프트 활성)로 ROC를 그려 고르고, 오탐률과 미탐률을 기록한다.
  - 비용: 토큰당 내적 1회로 무시할 수준이다.
- **R2-2. 적용 시점 (방식 A와 B 비교).**
  - **A. 요청 단위:** 프리필 끝에 점수를 보고 ON으로 바꾼다. 프롬프트 KV는 OFF 상태로 계산된 것이므로 두 가지를 비교한다.
    - A1: 생성부터만 ON
    - A2: 프롬프트 체크포인트에서 ON으로 다시 프리필
  - **B. 토큰 단위:** 디코드 중 매 토큰 점수를 보고, 임계값을 넘으면 그 토큰부터 계속 ON(sticky)으로 둔다. 답변 도중에 거절로 돌아서는 경우를 잡는다.
  - 참고: 조건부 활성 조향 CAST(Lee et al., ICLR 2025)가 같은 발상이다. 조건 벡터로 감지하고 조향 벡터를 적용한다.
- **R2-3. 엔진 반영.**
  - 세션 상태를 OFF에서 ON으로 바꾸면 그래프를 다시 기록하고 캐시 identity가 분리된다(SERVER.md). 그래서 전환 비용과 캐시 정책을 정해야 한다.
  - 응답에 `abliteration_triggered`, 점수, 전환 위치를 보고한다.
- **R2-4. 평가.** 다음 세 가지를 OFF, 항상 ON, 동적 세 설정에서 비교한다.
  - tuning48 거절률
  - 일반 질문 KL과 답변
  - 오탐 사례(일반 질문인데 ON이 된 경우)

**한계:**

- 거절이 아닌 순화(예: 천안문 답변의 공식 입장 쪽 서술)는 거절 방향으로 잡히지 않는다. 별도 방향(정치 순화)을 수집해야 한다.

## R3. 정치 순화(중국 공산당 민감 주제) 방향

- **2026-11-11 1차 결과:** KNOWHOW의 "Flash-Next political-sensitivity direction" 항목.
  - L19와 L38 방향의 평균(k=1)이 정치 평가 16개를 모두 사실대로 답했다.
  - 거절 방향만으로는 대만 질문의 공식 입장이 고쳐지지 않았다.
- **다음:**
  1. 정치 평균 방향과 거절 방향을 합친 프로파일을 만든다.
  2. 일반 질문 KL과 답변 품질(tuning48의 ordinary)을 확인한다.
  3. 거절 질문 거절률을 확인한다.
  4. 평가 질문을 늘린다. 학습에 쓰지 않은 주제를 넣고 사실 체크리스트로 채점한다.
  5. 결과가 좋으면 운영 기본 프로파일로 반영한다.
