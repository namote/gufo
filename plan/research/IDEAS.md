# 연구 아이디어 (2026-11-11 등록)

순서는 등록 순서다. 각 항목은 착수할 때 단계별 계획 문서로 옮긴다.

## R1. 양자화 오차 보정: EoRA, 그다음 층별 어댑터

**목표:** 비트를 낮춘 팩(3.0~3.5 bpw)에 작은 FP16 보정을 붙여 c03(4.04 bpw) 수준의 KL을 맞춘다. 디코드와 프리필 MoE 가중치 스트림이 비트 수에 비례해 줄어드는 만큼 빨라지는 것이 가치다. 4.04 bpw에 그냥 붙이면 연구 결과상 이득이 작다.

**단계:**

- **R1-1. EoRA 오프라인 계산 (학습 없음).**
  - 대상: attention과 GDN의 projection, 공유 전문가, LM head. MoE 전문가는 제외한다.
  - 방법:
    1. 원본 BF16 가중치와 EXL3 복원 가중치의 차이 `ΔW`를 구한다.
    2. 보정 활성값 공분산의 고유공간으로 옮긴 뒤 SVD한다. 랭크는 32~128.
  - 참조 경로(PyTorch, 블록 단위)에서 KL 개선을 측정한다. 효과가 없으면 여기서 멈춘다.
  - 원본: 외장 디스크 `AI/models/qwen3.8-flash-next/hf-bf16-20261030`.
  - 저비트 후보: 27B `exl3-w8 3.0/3.5bpw`, Flash-Next Kyojin 3.05. 새 양자화가 필요하면 사용자에게 먼저 묻는다.
- **R1-2. 층별 bottleneck 어댑터 (학습).**
  - 구조: 잔차 스트림에 `x + W2·σ(W1·x)`(2560→256→2560)를 넣고, EoRA 결과로 초기화한다.
  - 학습: 블록 단위 증류로 원본 블록 출력에 맞춘다. EXL3 블록 하나를 FP16으로 풀어 고정하고 어댑터만 학습한다.
  - 마지막으로 LM head를 top-k logit KL로 미세조정한다.
  - 일반화를 확인한다: 한국어, 코드, 긴 컨텍스트 KL을 학습 분포 밖에서 잰다.
- **R1-3. 엔진 반영.**
  - 어댑터 로더와 `y = EXL3(W)x + B(Ax)` 경로(디코드 GEMV, 프리필 GEMM)를 만든다.
  - 그래프 캡처, 배치 디코드, MTP 검증 경로에도 넣는다.
  - 판정: "저비트 + 보정"이 c03보다 빠르고 KL이 같거나 낮아야 채택한다.

**근거:**

- EoRA(arXiv 2410.21271): 학습 없이 몇 분이면 되고, GPTQModel에 통합돼 있다.
- LQER(ICML 2024): W4A8에서 rank 32로 PPL 증가 평균 0.15.
- PV-Tuning/AQLM, QuIP#/QTIP의 미세조정: 2비트에서 이득이 크다.
- exllamav3 README 기능 목록에 LoRA가 있다. gufo에는 LoRA 경로가 없다.

## R2. 동적 다중 프로파일 abliteration (감지했을 때만 켜기)

**목표:**

- 평소에는 OFF로 원본 그대로, 원본 속도로 답한다.
- 프로파일마다 감지기를 두고, 기준을 넘은 프로파일만 켠다. 프로파일은 서로 합치지 않고 따로 둔다(사용자 결정, 2026-11-11).

**근거 측정 (2026-11-11):**

- **감지 성능 (오프라인 ROC):** `build/b1/ablit-pol-20261111/roc.py`. 같은 주제의 다른 문장이 학습과 검증 절반에 섞여 있어 낙관적인 수치다.

| 감지기 | 층 | AUC | 일반 질문 오탐 1%일 때 재현율 |
| --- | --- | --- | --- |
| 정치 | L38 | 0.985 (대조 사건), 0.994 (일반 질문) | 81% |
| 거절 | L38 | 0.985 | 92% |

  - 거절 감지기는 중국 민감 질문의 66%에도 반응한다. 두 신호가 겹친다.
- **현재 ON의 속도 비용:** 운영 c03에서 같은 질문 256토큰, 4회씩 측정했다.
  - OFF 42.3 tok/s, ON(거절 프로파일 writer a2 m05) 38.7 tok/s로 **-8.5%**.
  - 패스마다 96곳에서 별도 projection 커널이 돈다.

**설계:**

- **설정:** `--abliteration-profiles DIR`
  - 디렉터리의 프로파일 각각이 방향, 강도, `trigger {layer, threshold, scope}`를 가진다.
  - 단일 옵션 원칙에 맞게 기존 `--abliteration-profile`을 대체하는 방향으로 검토한다.
- **감지:**
  - 패스마다 감지 층의 마지막 행(디코드는 각 행)에서 프로파일별 점수 `<h, d>`를 계산하는 작은 커널을 하나 돌린다.
  - **점수는 logits와 같은 전송으로 host에 보낸다.** 추가 동기화가 없다.
  - OFF 요청의 비용 목표는 0.5% 이하다.
- **적용:**
  - 프리필이 끝날 때 점수가 기준을 넘은 프로파일을 켠다.
  - 디코드 중에도 넘으면 그 토큰부터 계속 켜 둔다(sticky).
  - 여러 프로파일이 동시에 켜지면 방향들을 직교화해서 함께 제거한다(기존 k-direction 경로).
- **프롬프트 KV 처리:** 두 방식을 품질로 비교해 고른다.
  - A1: 생성부터만 ON
  - A2: 감지된 요청만 ON으로 다시 프리필
- **ON 비용 줄이기:**
  - projection을 기존 잔차 Combine 커널과 writer 경로에 합쳐서, ON 비용을 -8.5%에서 1~2% 수준으로 낮춘다.
  - 이 작업은 동적 방식과 별개로 항상 ON인 경우에도 이득이다.
- **보고:**
  - 응답에 `abliteration: {triggered: [...], scores: {...}, position}`를 넣는다.
  - `/props`에 로드된 프로파일과 기준치를 보여 준다.
- **캐시:**
  - 프로파일 조합마다 continuation identity를 분리한다(현행 ON/OFF 분리를 확장).
  - 전환할 때 그래프를 다시 기록하는 비용을 측정한다.

**단계:**

- **R2-1. 기준치 확정.**
  - 정치 평가 질문을 학습에 쓰지 않은 주제로 늘리고, 사실 체크리스트로 채점한다.
  - 일반 질문 KL과 답변 품질을 확인한다.
  - 기준치를 오탐 1% 이하에서 고른다.
- **R2-2. 엔진 구현.** 다중 프로파일 로드, 감지 커널, 점수 전송, 요청 중간 전환, 보고.
  - CPU/단위 테스트 → 검토 → 수정 → 재검토 순서로 진행한다.
- **R2-3. projection 커널 합치기.**
- **R2-4. 통합 확인** (GPU 1회):
  - OFF 속도가 지금과 같은지 (±0.5%)
  - 감지 정확도
  - 정치·거절·일반 질문 품질
  - A1과 A2 비교
  - 캐시 재사용과 분리
- **R2-5. 운영 반영.**

**한계:**

- 거절 방향만으로는 순화(공식 입장 서술)를 잡지 못한다. 그래서 정치 프로파일을 따로 둔다(R3).
