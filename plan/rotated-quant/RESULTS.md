# RQ 효율 점수판 (Qwen3.8 27B)

상위 문서: [회전 가중치 양자화 계획](PLAN.md) "효율 점수판". 모든 실험(R0 기준선 포함)을 이 한 표에 쌓는다. 표의 틀은 W2가 만들었다(2026-10-29). 이후 갱신은 감독이 한다.

## 측정 규칙

- **품질:** BF16 대비 값이다. 표의 품질 값은 prefill 경로이고, 괄호는 토큰 단위 95% 구간이다. verify·decode 경로와 블록·창 구간, 카테고리별 값은 [R0 결과](R0-RESULTS.md)에 있다. 수집기는 `qwen27b_rq_logits`, 지표는 `tools/qwen27b/rq_quality/metrics.py`로 낸다. 코퍼스 a01: 32,760 위치, `windows.bin` sha256 `ee0d9ba3…791c`.
  - 각 값 뒤의 괄호는 토큰 단위 paired bootstrap 95% 구간이다. 블록(256토큰)·창 단위 구간은 R0-RESULTS 같은 단계별 결과 문서에 둔다.
  - 경로는 prefill(전체), verify(전체), decode(창마다 prefix 2048 뒤 512위치) 셋이다. 표에는 prefill 값을 넣고, 경로 간 차이는 단계별 결과 문서에 둔다.
- **같은 수집기:** R0, R2 ②, R4의 품질 비교는 같은 툴체인과 같은 수집기 바이너리(sha)로 한다(감독 2026-10-29). 바이너리가 바뀌면 BF16 기준부터 다시 수집한다.
  - 고정 바이너리 sha256 `5ed60166…d0c0`(v3 트리, 2026-10-29 10:46 작업 트리 스냅샷: HEAD `32dbf0fc` + `git diff HEAD` sha256 `916bfef7…`). top-k 256으로 고정한다. ROCm 7.2.4 gpu-test, 이미지 `ai-tools/gufo-eval:64849ca6ec7b`.
- **속도:** 운영과 같은 rocm101 측정 빌드를 쓴다.
  - 요청·단계별 5 % 또는 10 ms 기준으로 판정한다.
  - 같은 파일을 번갈아 돌려 잡음 폭을 기록한다.
  - 잡음이 크면 "결론 없음"으로 둔다.
- **크기:** 평균 bpw는 output을 포함하고 임베딩과 NextN 블록(`blk.64`)을 제외한 2차원 가중치 텐서 기준이다. 상주 메모리는 HIP가 보고한 최대값이다.
- **채택 후보:** 품질 대 바이트, 품질 대 실효 tok/s의 파레토 앞쪽에 있는 설정에 ★를 붙인다. D4 수치 기준은 R0 결과를 보고 사용자가 정한다.
